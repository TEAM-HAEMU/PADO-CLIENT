## 빌드 선택

| 빌드 | 내용 | 재제출용 |
|---|---|---|
| 1.0 (2) | 반려 항목 수정 포함 | **권장**. 이미 버전에 연결돼 있다 |
| 1.0 (3) | 1.0 (2) + 비밀번호 재설정 | 백엔드 메일(SES)이 운영 승인 전이면 쓰지 않는다. 심사자가 "비밀번호를 잊으셨나요?"를 눌렀을 때 메일 발송 실패(U25)가 나면 2.1(완성도) 반려 사유가 된다 |

SES 승인이 나서 실제 메일로 처음부터 끝까지 확인한 뒤에는 1.0 (3)으로 바꿔도 된다. 바꾸면 심사 메모 첫 줄의 빌드 번호도 고친다.

## 재제출 전에 사람이 확인할 것

1. **앱 개인정보(App Privacy) 라벨**: API로는 볼 수 없어서 웹에서 확인해야 한다. 분석을 켠 사용자에 한해 Amplitude가 정밀 위치, 사용 데이터(화면, 탭, 세션 리플레이), 사용자 ID를 보낸다. 라벨에 "사용자에게 연결됨, 추적 아님, 분석 목적"으로 적혀 있는지 본다.
2. **5.2.3 처리 방식**: 아래 둘 중 하나를 고른다.
   - Apple 답을 기다린다 (보통 1~3일, 답이 오면 메일로 알림이 온다).
   - 답을 기다리지 않고 "앱 심사에 다시 제출"을 누른다. 회신 스레드는 그대로 남아 심사자가 함께 본다.
3. 위 두 가지가 정리되면 App Store Connect › 앱 심사 › **앱 심사에 다시 제출**. 제출은 사람이 직접 누른다.

## 5.2.3이 다시 반려되면

회신에 적은 대안: 곡 검색과 앨범 아트를 Spotify Web API에서 Apple Music 카탈로그(MusicKit / iTunes Search)로 옮긴다. 미리듣기는 이미 iTunes다. 서버 검색 API와 앱 화면을 함께 바꿔야 하므로 백엔드와 일정을 맞춘다.
